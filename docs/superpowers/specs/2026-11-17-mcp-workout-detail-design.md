# Workout details through MCP and export

User approved both richer MCP access and web export, prioritizing MCP. Existing OAuth/RLS remains authoritative; no schema, sync, token or permission changes. The observed example is Concept2 workout 98848028: 748 stored samples and 6 splits, currently omitted by MCP.

A dependency-free `shared/workoutDetail.ts` defines a versioned JSON representation consumed by the Vercel API and browser. Include stable LC/external IDs, summary, saved/manual structure and template link, measured splits separately from workout intervals, normalized samples and explicit units/availability. Concept2 t/d/p use deciseconds/decimeters/deciseconds-per-500m; derive watts using the rowing erg formula. Unknown source encodings must be reported unsupported rather than guessed. Preserve sequence and segment boundaries at clock resets; do not sort or invent timestamps. Invalid values become null or rejected samples with counts.

`get_workout` remains compact and compatible, adding normalized structure, splits and sample availability/count. `get_workout_samples` returns at most 500 samples per page, explicit offset/next offset/total and optional time window; IDs may be LC UUID, C2 external ID or an LC workout URL. `analyze_workout` computes time strictly above a supplied HR threshold using linear interpolation between valid adjacent samples in the same time segment; skip gaps over 10 seconds by default, missing HR and non-increasing timestamps. Report method, covered time, excluded gaps and sample span. No extrapolation before/after samples. Missing/unsupported data yields unavailable, never false zero.

Workout page adds a shared Button/Select export control with JSON and sample CSV. Fetch authoritative owner-visible workout row on demand through the browser Supabase client and normalize with the same module. JSON includes summary, structure, samples, units and provenance. CSV has numeric normalized samples with header units and segment index; disable CSV when no supported valid samples and explain why, while JSON remains possible. Export failures are actionable; busy state prevents double download and scope changes discard stale results. No production writes or deployment within this implementation.
